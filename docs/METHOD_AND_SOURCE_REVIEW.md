# Scope and source review

The initially empty workspace had no local copies of the attachment filenames, project conventions, or manuscript tree. The complete manuscript and both scripts pasted into the assignment were the supplied source materials. No unrelated manuscript section has been edited. The generated `paper_subsection.tex` is an insertion proposal.

## Reuse of the supplied implementation

`scoring.py` preserves the principal `load_text_embeddings`, `extract_dense_image_embeddings`, and `compute_max_over_patches_similarity` interfaces and refactors their normalization, official dense API calls, concept chunking and maximum reduction. `ImageInferenceDataset`, `collate_fn`, and the optional dense-head batch path adapt the detection script. Rank-by-mean-difference selection is retained, but operates on canonical weighted comparisons. The application writers preserve signs, unlike the supplied absolute-difference writer. The unrelated detection benchmarks, threshold optimization, hard-coded cluster paths, zero-filled failures and ordinal-rank AUROC were not imported.

## Pinned sources

Exact revisions, schemas, repository file sizes, downloaded metadata hashes, and model source paths are in `reports/source_inspection/source_inspection.json` and `configs/sources.lock.json`.

- [ImageReward dataset](https://huggingface.co/datasets/zai-org/ImageRewardDB), [pinned loader](https://huggingface.co/datasets/zai-org/ImageRewardDB/blob/c493721e19e296eb615420036f2a2eed08412bb4/ImageRewardDB.py): the loader branches on `rank[idx] < rank[idy]` to choose the better image. We read metadata parquet directly and group explicit prompt IDs, rather than execute its old loader or rely on row adjacency.
- [ImageReward paper](https://proceedings.neurips.cc/paper_files/paper/2023/file/33646ef0ed554145eab65f6250fab0c9-Paper-Conference.pdf): human ratings and rankings are distinct annotations. Our primary outcome uses rankings only; ratings are preserved.
- [Pick-a-Pic rankings](https://huggingface.co/datasets/yuvalkirstain/PickaPic-rankings) and [images](https://huggingface.co/datasets/yuvalkirstain/PickaPic-images): these specific January 2023 tables define the application cohort. Four displayed UIDs and a selected UID do not imply a total ranking.
- [Pick-a-Pic paper](https://proceedings.neurips.cc/paper_files/paper/2023/file/73aacd8b3b05b4b503d58310b523553c-Paper-Conference.pdf): describes experiments with four-image and pairwise annotation protocols. The final paper's commonly used pairwise release is not interchangeable with the supplied four-candidate tables.
- [Supplied bank](https://huggingface.co/datasets/LGirrbach/fg-clip-text-embeddings/tree/4edc5ef4ac601a3d08225b53567b6695cbd60b5e): 54,030 unique terms and a finite 54,030 × 768 tensor; no generation metadata, frequency ordering, or COCA-20k identity is asserted. Safe tensor loading uses `weights_only=True`. Original files remain unchanged.
- [FG-CLIP2 model example](https://huggingface.co/qihoo360/fg-clip2-base/blob/430fbc8a912c86fd4de601381b6245a0edab22f0/README.md): dense alignment uses lowercased text, max length 64 and `walk_type="box"`. We diagnose compatibility against that mode plus documented short/long modes, without regenerating the bank.

The pinned `configuration_fgclip2.py` and `modeling_fgclip2.py` were downloaded and read before execution. They define the model, Torch/Transformers operations and region pooling; external URL usage found by inspection occurs in docstring examples. `trust_remote_code` is restricted to the pinned model/code commit. The current code imports newer Transformers internals; the isolated environment uses Transformers 4.57.6, tokenizers 0.22.2 and huggingface-hub 0.36.2. No obsolete dataset script is executed. Processor geometry is SigLIP2 row-major HWC patches with a valid-prefix attention mask. Heatmaps invert the exact processed patch tensor, including normalization and resizing.

The real smoke audit compared twelve evenly spaced vocabulary entries in float32. Mean cosine to the original bank was 0.6770 for box (minimum 0.4235), 0.3944 for short and 0.3626 for long. Box was closest but this is not a reproduction of the bank. Its source encoder/template remains unresolved, so semantic interpretations must remain provisional. The bank was retained, not regenerated. The official float32 single-image reference and production path agreed exactly on GPU; the optional batch path has its own separate GPU test.

That separate real GPU test passed in pilot job 1863492: the dense-head batch implementation differed from the official single-image FP32 reference by at most 1.19e-7 on two images with contrasting aspect ratios and 128 evenly spaced concepts. The production pilot still used batch size one. At least one ImageReward decode failure was verified as an actual zero-byte member of the pinned source ZIP, with the ZIP read/CRC check succeeding; see `reports/source_inspection/imagereward_decode_failure_probe.json`.

The continuation tested 32 evenly spaced bank entries with 11 fixed templates, three documented modes and two actual attention-mask settings (66 configurations, four GPU workers). Version 2 explicitly requests a tokenizer mask for the masked branch: this tokenizer normally returns only `input_ids`. The closest setting was `walk_type="box"`, template `a photo of a {}.`, **without** an attention mask, mean cosine 0.965598 and minimum 0.872059; all 32 re-encoded vectors retrieved their own bank entry as nearest neighbor. This supports compatibility with templated box text but does not exactly recover the original recipe. The best mean cosine among the explicitly masked settings was only 0.184254. No bank rows were replaced. The earlier version-1 diagnostic inadvertently omitted masks in both branches and is retained with an explicit correction; version 2 is authoritative. See `reports/source_inspection/text_bank_template_diagnostic.json`.

Four-GPU recomputation of 22 real images across the full 54,030-concept bank agreed exactly with the single-GPU cache (job 1863775). The 500-prompt primary pilot used the unchanged FP32 single-image API independently on four GPUs; image aliases were kept together, and separate worker caches were merged only after committed rows became available. Fingerprints prevent incompatible bank/model/preprocessing/precision changes from being reused.

The largest full-bank score difference was 8.3447e-7, below the predeclared 2e-4 tolerance; each worker also passed its official FP32 reference gate. Invalid-image statuses matched. Fresh scheduler jobs use this validated batching, while the primary reported analysis keeps its original single-image scores and discovery-frozen candidates.

## Statistical choices and adjustments

The estimator first averages strict oriented comparisons within each event, then events within each normalized prompt, then prompts. Side-specific weighted means obey the same estimand. Numerical equality uses a fixed configured tie tolerance, zero by default. The raw paired concordance is preferred-higher plus half ties. Direction-adjusted concordance uses only discovery directions. Marginal tie-correct AUROC is a tested optional helper; it does not replace paired metrics.

ImageReward uses official split labels. Entire connected prompt/image components crossing official boundaries are quarantined. Pick-a-Pic shuffles sorted independent component IDs with NumPy PCG64 and seed 42, then applies largest-remainder 70/15/15 allocation. Components are conservatively formed across all recorded events, including excluded events that link images. Prompt normalization is Unicode NFC and whitespace collapse only. Known incompatible or partly missing negative prompts exclude strict Pick-a-Pic events; all-null negative prompts remain marked unknown. Normalized positive prompts remain the aggregation/leakage grouping even when negative prompts differ between events.

Pilot sampling is deterministic whole-component sampling with 70/15/15 prompt caps inside fixed partitions; it is not proportional to the original official split sizes. A small quota can undershoot if a component does not fit. Groups lost to image failures are not replenished. All comparisons from an event are excluded if any displayed candidate cannot be resolved/scored, including tied candidates unused by a sensitivity construction.

The primary candidate list is the strictly signed top ten per side. Alternatives are not substituted when held-out effects fail. Complete all-concept validation/test columns are labeled exploratory; only the frozen list receives default bootstrap computation. The joint score is an equal signed mean of frozen concept scores, without fitted weights. ImageReward construction sensitivities each have separately frozen discovery lists; generator/geometry subgroup sensitivities use the primary frozen list.

Cluster bootstrap samples components uniformly with replacement but weights their summed prompt values by sampled prompt counts. This retains the prompt estimand rather than weighting large and small components equally. The annotator sensitivity unions prompt/image components sharing users and retains the same point estimate, potentially yielding very few clusters. No formal whole-vocabulary significance testing or causal attribution is performed.

## Environment and availability

The login-node sandbox initially could not create namespaces; execution continued after the session changed to unrestricted permissions. All GPU work uses Slurm. `$SCRATCH` returned disk-quota errors, so bounded run artifacts use ignored `runs/` on project storage. Persistent metadata, images, bank and model files use `$PROJECT/avrecum/.hf`. ImageReward ZIP member byte ranges avoid whole-archive downloads. Each image is decoded before becoming valid.

Compute nodes have no outbound network access. The initial smoke job spent time in Hugging Face retries for optional tokenizer files before completing; subsequent scoring is explicitly local-only and the scheduler scripts set offline environment flags. `prefetch` resolves all actual model/tokenizer files beforehand. The optional inherited numerical environment also exposes unrelated vLLM/segmentation package metadata; `pip check` reports their incompatible Transformers/Hub requirements inside this application venv. Those packages are not used here and their original environment is unchanged. A fresh environment installed from this project's extras avoids that inherited metadata conflict.

All 119 selected Pick-a-Pic smoke images returned HTTP 403 from their original AWS URLs. [The authors document obsolete direct URLs](https://github.com/yuvalkirstain/PickScore#download-the-pick-a-pic-dataset). The four alternate v1/v2 and no-images Hub endpoints checked returned HTTP 401; this does not establish whether they are private, gated or absent. No alternate release was substituted. A local cache of the original UID-named images can be supplied to the adapter. Until such bytes are available, empirical Pick-a-Pic effects and cross-dataset replication are unavailable.

Further bounded recovery inspected the authors' public `pick_a_pic_ranked_images_first_day` and `pick_a_pic_preferred_images_first_day` parquet schemas and UID columns. Their union contains 1,001 UIDs, 959 also present in the original image table, but **zero complete strict four-candidate events**. Among the 13,085 eligible original events, available candidate counts were 12,374 with zero, 513 with one and 198 with two; none had three or four. An accessible CarperAI pairwise index had 359,884 distinct UIDs and zero original-UID overlap. The public `pickapic-anonymous/pickapic_v1` archive was found, but exact UID viewer queries timed out; that is not evidence of absence from the archive. Revisions, schemas, coverage and timeouts are saved in the `pickapic_*` continuation audit files. These sources were considered only for original-UID-verifiable image recovery; none of their preference labels replaced the original rankings.
